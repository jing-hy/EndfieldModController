# 三件套路线（DLSS5 + 第一人称 + 服装 Mod）

> 2026-09-27 改造。做法来自 B 站教程 **BV1XMh76UEA5**（UP：白马腚叫他有来无回，含 P2 补充），本机已实测通过。
> 旧注入路线已废弃，见文末「废弃清单」。

## 一、原理（为什么只能有一个 ReShade）

第一人称 enhancer 和 DLSS5 各自都带一个 ReShade 底座（`d3d12.dll` / `dxgi.dll`）。同一个游戏进程里**只能有一个 d3d12.dll 代理命中** —— EFMI 先注入一个之后，游戏再加载同名模块时 Windows 直接返回已注入的那份，第二份永远不生效，表现就是「DLSS5 正常但 enhancer 不启动」或「EFMI 加载失败」。

所以正确做法是：**只留一个 ReShade 底座，让两个插件挂在它下面**，再由 XXMI 把「这个唯一底座」和「EFMI 服装 Mod 引擎」一起注入。

## 二、本机布局（全部内置，不依赖外部目录）

```text
endfieldmodcontroller/
├─ runtime/
│  ├─ dlss5/                         ← 唯一 ReShade 底座（128 MB）
│  │  ├─ d3d12.dll                   ← 被 XXMI 注入的就是它
│  │  ├─ ReShade.ini                 ← [endfield-enhancer] 段置顶 + [GENERAL]（绝对路径）
│  │  ├─ renodx-dlss5-4.7_汉化.addon64
│  │  ├─ renodx-endfield-enhancer.addon64
│  │  ├─ dlss5-feed.addon64 / trans-zh.addon64 / translations.txt
│  │  └─ reshade-shaders/            ← 1055 个 shader/贴图，含 DLSS5_Feed.fx
│  └─ builtin/XXMI/                  ← 内置 XXMI Launcher 2.2.1 + EFMI 1.4.7
│     ├─ Resources/Bin/XXMI Launcher.exe
│     └─ EFMI/
│        ├─ d3d11.dll                ← 服装 Mod 引擎（注入用）
│        └─ Mods/                    ← MC_* = 本程序 staging 的 Mod
└─ library/                          ← 外部 Mod 库（只读），UI 里挑选
```

游戏目录（`D:\Hypergryph Launcher\games\Endfield Game`）**不写任何** ReShade / addon 文件；只需 `nvngx_dlss.dll`（58,977,904 B）与 `nvngx_dlssnr.dll`（165,840,496 B）两个运行库在位。

## 三、注入库由程序维护

XXMI 的 `XXMI Launcher Config.json` → `Importers.EFMI.Importer`：

```json
{
  "extra_libraries_enabled": true,
  "extra_libraries": "D:\\zmdmod\\modecontroller\\runtime\\dlss5\\d3d12.dll\nD:\\zmdmod\\modecontroller\\runtime\\builtin\\XXMI\\EFMI\\d3d11.dll"
}
```

- 启动页「三件套注入」开关 = 写入 / 清空上面这两条（等价于 XXMI 界面上「设置 → 高级 → 注入库」）。
- 首次改写后，XXMI 可能弹一次签名确认（它用本机 ECDSA 密钥给该设置签名），点一次 **Keep / 保留** 即可；备份在 `XXMI Launcher Config.json.mc.bak`。
- 关闭开关后只剩服装 Mod 生效，可随时切回来。

## 四、进游戏后的设置（按 Home）

| 位置 | 项 | 值 |
|---|---|---|
| 插件页 | 应有 | **RenoDX-DLSS5** + **Endfield Enhancer** 两个 |
| RenoDX-DLSS5 | 启用DLSS神经渲染 / 启用超分 (WIP) | 都勾 |
| RenoDX-DLSS5 | NR风格 | 电影（游戏本身偏写实会偏黑，自然/电影偏白） |
| RenoDX-DLSS5 | 总体强度 / 结构强度 | 拉满；局部色调 1.20；角色/皮肤结构 ≥ 0（用 0.70） |
| Endfield Enhancer → Camera | Camera Controls | **先 On**（不开这个相机功能用不了） |
| 同上 | First Person | On |
| 同上 | Third Person During Combat | **Off**（否则打 boss 会被强制踢出第一人称） |
| 同上 | EFMI / XXMI Compatibility | **On**（和服装 Mod 共存的关键） |
| 同上 | Field of View | 跑图 60，打 boss 拉到 80 |

快捷键：`F6` 神经渲染开关 · `F5` 截图 · `F11` Mod 显示（屏幕上方 `Mods Display: Enabled`） · `,` 第一人称 · `F12` EFMI 帮助 · `Home` ReShade 面板。

## 五、常见问题

**插件页只有 DLSS5，没有 Enhancer**
→ `runtime\dlss5\renodx-endfield-enhancer.addon64` 不在；或游戏目录里还留着旧的 ReShade 抢了 hook（用启动页「检查游戏目录注入 / 清理残留注入」）。

**注入后弹出 “DLSS5 / D3D12 驱动” 之类报错**
→ 通常是两个 `d3d12.dll` 同时注入了。检查 XXMI 注入库只保留一条 `d3d12.dll`。

**服装 Mod 不生效但 ReShade 正常**
→ 同一角色放了两个 Mod（Mods 里出现两个同角色目录）；本程序 staging 时已做同角色互斥，手动往 `Mods` 扔的副本会绕过它，请清掉手动的。

**完整性检查报 controller.ini / actions.tsv 缺失**
→ 正常，点一次「生成控制器」即可（启动时也会自动补）。

## 六、乳摇插件（SecondaryMotion）集成

第三方工具 `ShakingBreastManager-v2.3.5-ZH-win-x64`（仓库：[Sp1cHless/Arknights-Endfield-Plugin-Secondary-bodyphysics](https://github.com/Sp1cHless/Arknights-Endfield-Plugin-Secondary-bodyphysics)）**保持原样独立运行**，本程序只做四件事：

| 能力 | 入口 | 说明 |
|---|---|---|
| 状态显示 | 启动页 · 乳摇状态块 | 工具版本 / exe / 两个 proxy / `plugin\sbm.dll` / 运行时 `runtime_status.json`（state、mode、当前角色、几秒前）/ 插件日志尾部 |
| 启动它原生界面 | 启动页「启动乳摇管理器」 | 直接拉起 `SecondaryMotion.Manager.exe`，工具界面不变 |
| 补齐注入 | 启动页「补齐乳摇注入」＋ 启动时自动 | 缺哪个补哪个：`d3dcompiler_47.dll`(14336) / `vulkan-1.dll`(35328) 两个 proxy + `plugin\sbm.dll`；原版一律先备份成 `.bak` |
| 卸载注入 | 启动页「卸载乳摇注入」 | 删 proxy、把 `.bak` 还原成正式 DLL、停用 `plugin\sbm.dll` |

它的注入链与三件套互不冲突（文件名不重叠），但**它替换的是 `d3dcompiler_47.dll`**：如果 ReShade 或服装 Mod 突然失效，先把这一项卸掉验证。

## 七、组件更新

启动页「检查组件更新 / 更新 ReShade 底座 / 更新乳摇插件」：

| 组件 | 当前版本 | 更新来源 |
|---|---|---|
| ReShade 底座 `d3d12.dll` | 6.8.0.2155 | reshade.me 官方 `ReShade_Setup_<ver>_Addon.exe`，解包后替换，旧版存 `d3d12.dll.bak-<时间戳>` |
| 乳摇插件 | v2.3.5 | GitHub release 里最新的 `ShakingBreastManager-v*-ZH-win-x64.zip`，替换工具目录，保留 logs/presets/data/settings.json，旧版整体备份到 `_backup_<时间戳>` |
| DLSS5 相关插件 | RenoDX DLSS5 v4.7 | 随 `runtime\dlss5` 一起管理（导入素材包时更新） |
| XXMI / EFMI | 2.2.1 / 1.1.7 / 1.4.7 | 由 XXMI Launcher 自身更新 |

> 注意：官方新版 ReShade 可能与 DLSS5 插件不兼容（本方案实测版本是 **6.8.0**）。更新后若 DLSS5 神经渲染不工作，把 `d3d12.dll.bak-*` 改回 `d3d12.dll` 即可回退。

## 八、启动时的初始化自检（一键启动自动补齐）

**XXMI 自己负责的注入不算在内**——把 `d3d12.dll` / `d3d11.dll` 注进游戏进程是 XXMI 干的活，控制器只保证「注入库配置写对了」。除此之外，凡是需要「先落到磁盘上」的东西，启动时逐项校验，缺什么补什么。

实现：`launcher.ensure_injections()` → `initialize.ensure_all()`（也可在启动页点「一键初始化自检」手动跑）。

| # | 检查项 | 缺了怎么办 | 补齐来源 |
|---|---|---|---|
| 1 | XXMI 注入库两条路径 | 重写 `XXMI Launcher Config.json` | 内置路径 |
| 2 | `runtime\dlss5\d3d12.dll` | 复制回来 | `dlss5_source_dir` → `D:\zmdmod\DLSS5` → 终末地素材 → runtime\backups |
| 3 | `dlss5-feed.addon64` | 复制回来 | 同上 |
| 4 | `renodx-endfield-enhancer.addon64` | 复制回来 | 同上 |
| 5 | `trans-zh.addon64` | 复制回来 | 同上 |
| 6 | `renodx-dlss5*.addon64` | 复制回来（按通配符找） | 同上 |
| 7 | `reshade-shaders\Shaders\DLSS5_Feed.fx` | 解压整个 shader 包 | 素材目录的 `reshade-shaders.zip` |
| 8 | `ReShade.ini` 存在且含 `[endfield-enhancer]` 段 | 用模板 + 历史备份里的 enhancer 段**重建**（旧文件存 `.ini.bak-before-rebuild`） | `ReShade.ini.dlss5-template`、`_backup_before_dlss5\ReShade.ini` |
| 9 | ini 内路径指向当前 dlss5 目录 | 重写 4 个路径键 | 按当前目录生成 |
| 10 | 游戏目录 `nvngx_dlss.dll` / `nvngx_dlssnr.dll` | 从内置副本补齐（游戏原版备份成 `*.game_original`） | `runtime\dlss5` |
| 11 | `controller.ini` + `actions.tsv` | 重新跑一次 staging 与控制器生成 | library + selected_mods |
| 12 | 选中的 Mod 是否已 staging | 重新 staging（同角色互斥） | library |
| 13 | 乳摇两个 proxy + `plugin\sbm.dll` | 逐项补齐（原版留 `.bak`） | 工具自己的 `plugin\` |

- 每项结果都进报告：`就绪` / `已补齐` / `待处理`；补不了的项目（例如素材目录不存在）会明确标成待人工处理，并在启动日志里打 `WARN 初始化: ...`，而不是静默启动。
- 全部动作可回滚：补齐前该备份的都会备份。

**实测**（故意破坏三处后跑自检）：把 `dlss5-feed.addon64` 改名、把 ini 的 `[endfield-enhancer]` 段改名、把 `plugin\sbm.dll` 改名 → 自检 13/13 就绪、3 项自动补回、0 项待人工。

## 九、废弃清单（旧的注入路线，代码保留但不再走）

- 外部注入 `ReShade64.dll`（`reshade_injection=external`）与本程序自己的注入线程
- XXMI `custom_launch_inject_mode=Bypass` 顺序注入
- 自研 loader / `mc_bootstrap.dll` 进程内桥
- 「反作弊兼容模式」写游戏目录集成文件（`endfieldmodcontroller.addon64` / `actions.tsv` / `user_ini_path.txt`）
- 「dxgi 改名 d3d12 模式」与游戏目录 proxy
- 3DMigoto loader 路线（`runtime/migoto`）

这些入口在 UI 上仍有按钮的，一律不再参与新方案；如需彻底删除可后续清理。
