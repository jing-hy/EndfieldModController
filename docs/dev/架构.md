# 架构

## 外部管理器

Python + PyWebview + 静态前端。

- `config.py`：读写 `config.json`。
- `core.py`：库扫描、INI 解析、动作提取、控制器生成、`d3dx_user.ini` 写入。
- `activation.py`：冲突解析、依赖解析、staging、快捷键 patch。
- `dependencies.py`：依赖清单、URL/GitHub/GameBanana 下载、解压和更新。
- `launcher.py`：准备 ReShade runtime、检测已有 ReShade、构建 XXMI 启动命令。
- `reshade_integration.py`：检测游戏目录 ReShade，写入/回滚 3 个集成文件。
- `api.py`：前端调用入口。
- `app.py`：Pywebview 窗口。

## 数据流

```text
library/
  -> scan / metadata
  -> resolve_active_set (同角色互斥 + 依赖)
  -> copy to staging_mods_dir
  -> patch hotkeys in staging copies
  -> generate staging_mods_dir/_controller/controller.ini
  -> copy actions.tsv to runtime/reshade
  -> copy endfieldmodcontroller.addon to runtime/reshade/Addons
  -> if game dir has ReShade: deploy endfieldmodcontroller.addon64 + actions.tsv + user_ini_path.txt
  -> open XXMI Launcher (no --xxmi, so it does not auto-start the game)
```

## 游戏内

```text
ReShade Addon
  -> reads runtime/reshade/actions.tsv
  -> draws ImGui panel
  -> user clicks action
  -> writes runtime/EFMI/d3dx_user.ini:
       $\mc_controller\controller_action = <id>
       $\mc_controller\controller_value = <value>
  -> sends F10
EFMI reloads
  -> staging_mods_dir/_controller/controller.ini [Present] runs
  -> sets target variable or runs target CommandList
Original mod hotkeys were disabled in staging copies.
```

## 游戏目录写入边界

- 没有检测到已有 ReShade 时：ReShade base path 由 `RESHADE_BASE_PATH_OVERRIDE` 指向 `runtime/reshade`；`external` 只对运行中的 `Endfield.exe` 做 DLL 注入；`xxmi_extra` 只改 XXMI Launcher 配置文件。
- 检测到游戏目录已有 `ReShade.ini` + `dxgi.dll`/`d3d12.dll` 时：跳过外部注入，只写入 3 个集成文件 `endfieldmodcontroller.addon64`、`actions.tsv`、`user_ini_path.txt`，并在 `runtime/existing_reshade_files.json` 记录清单以便回滚。
- 不会改名或覆盖 `dxgi.dll` / `d3d12.dll` / `ReShade.ini`。
- Mod patch 只作用于 staging 副本，`library` 始终是原始下载。

## 已知技术约束

- ReShade Addon 和 3DMigoto 没有公开 IPC；所以使用 `d3dx_user.ini` + F10 动作队列。
- F10 重载时间与 Mod 数量正相关。
- CommandList 必须使用完整 namespaced section 名。
- 变量必须是 `global` 才能跨 namespace 写入。
