## 1. 需求与硬性约束（接手后不要违反）

| 约束 | 说明 |
|---|---|
| 一键启动必须走官方 XXMI/EFMI 图形界面 | 原话：*"要不然直接就是一键启动官方的 xxmi 和 efmi 的图像化界面，不要自己乱改"*。`launch_official_gui()` 只做 staging + 启动 `XXMI Launcher.exe`，不写游戏目录、不改 ReShade、不指定 game-dir |

```

        │
        ├── core.py                扫库/解析 Mod/冲突组/ini 处理/sanitize_ini_control_flow
```

### 5.4 NVIDIA 侧（外部"关不掉 DLSS"的真相）

全局 AI插帧（Smooth Motion）**本来就是关的**，但 NVIDIA App 会给**每个游戏单独**存 DLSS 覆盖：

```
%LOCALAPPDATA%\NVIDIA Corporation\NVIDIA App\NvBackend\ApplicationStorage.json
%LOCALAPPDATA%\NVIDIA Corporation\NVIDIA App\NvBackend\ngxdlssoverridestate.json
```

| 程序 | Disable_FG_Override | Disable_SR_Override | pinned SL |
|---|---|---|---|
| **Arknights: Endfield**（localId 1905992949） | **false → 覆盖生效** | **false → 覆盖生效** | **2.7.15** |
| DCS / Cities: Skylines 2 / War Thunder 等 | true | true | — |

`ngxdlssoverridestate.json` 里 Endfield 是 `stateMaskSR=5, stateMaskFG=5, stateMaskRR=1`，没开覆盖的游戏全是 `0`。

这解释了崩溃栈里的 `nvngx_dlssg.dll` / `sl.dlss.dll` / `d3d12.dll`（帧生成只在 DX12 存在）。
**关闭方法**：NVIDIA App → 图形 → 选中「Arknights: Endfield」→ 驱动程序设置 → DLSS 覆盖 → 「帧生成」「超分辨率」都设为「使用应用程序设置」。
⚠️ 这两个 json 由 NVIDIA App 自己重写，**不要手工编辑**（会在下次启动被覆盖，还可能写坏配置）。

`Player-prev.log` = **11:49 那次 XXMI 注入运行**（最后写入 11:52:51），同样是 **3430 帧 + Unity 正常退出统计**，不是秒崩。

### 6.3 本次修掉的代码 bug：`user_ini_path` 推导不一致

`activation.stage_and_prepare()` 在未显式传 `user_ini_path` 时用 `runtime_dir / "EFMI" / "d3dx_user.ini"` 推导；
但真实 staging 在 `runtime/builtin/XXMI/EFMI/Mods` 下，`AppConfig.user_ini_path`（正确实现）用的是 `staging_mods_path.parent`。
后果：UI 点「生成控制器」后 `runtime\reshade\user_ini_path.txt` 指向**过时目录** `runtime\EFMI\d3dx_user.ini`（该目录存在，于是静默写错文件），ReShade Addon 按它写动作队列 → 游戏内点击无效。
已统一为 `staging_root.parent / "d3dx_user.ini"`（与 `AppConfig.user_ini_path` 同规则，旧布局行为不变）；补回归测试 `tests/test_activation.py::test_user_ini_follows_builtin_staging_layout` —— 原有测试全部使用旧布局 `runtime/EFMI/Mods`，所以此前测不出该 bug。**37 passed**。
真实配置下已复核：`prepare()` 返回 `user_ini_path = ...\runtime\builtin\XXMI\EFMI\d3dx_user.ini`，`runtime\reshade\user_ini_path.txt` 同步一致，`d3dx_user.ini` 按新规则写入。

### 6.5 ⚠️ 不要补 `game_dir_injections.json`

游戏目录里的停放项是**早期手工/其他工具**做的，不是控制器 `disable_game_dir_injections()` 的产物，所以 `runtime\game_dir_injections.json` 不存在、UI 的「撤销清理」按钮当前无效——**这是安全的，不要去"修"**。

原因：`restore_game_dir_injections()` 会把 `entries[].disabled` **改名回原名**，等于一键把第三方加载器代理放回游戏目录（`d3dcompiler_47.dll` / `vulkan-1.dll` 变回 loader 代理、`plugin\sbm.dll` 复活），直接摧毁刚建立的干净基线。而且它只认 `*.loader.endfieldmodcontroller.disabled` 与 `plugin\*.endfieldmodcontroller.disabled` 两种后缀，游戏目录里那批 ReShade 类停放项（`d3d12.dll.endfieldmodcontroller.disabled` / `endfieldmodcontroller.addon.endfieldmodcontroller.disabled` 等）本来就不归它管。
要恢复只能按 §8.1 手工改名。

   - 启动页 → 「启动官方 XXMI / EFMI 界面」→ 在 XXMI 里点 **Start**；
   - 看能否过加载界面进游戏。
   判读：**能进** → 根因在第三方 `sbm.dll` / 加载器代理，Mod 路线继续；**仍退** → 根因在 EFMI 注入本身（反作弊），转 §5.4 / DDU 那条线。
   辅助手段：游戏启动后抓 `Endfield.exe` 的模块列表，确认 `EFMI\d3d11.dll` 是否真的注入、有无其他第三方模块混入。
3. **【用户操作】关闭终末地的 DLSS 覆盖**（见 5.4）。全局 AI插帧已经关了，不用再动。
4. **【需要时】若仍闪退**：
   - 整套一致安装 XXMI-Libs **v1.1.9 prerelease**（DLL + `Manifest.json` 同步）；
   - 或 DDU 后重装稳定版 NVIDIA 驱动；
   - DLSS Swapper 统一三件套版本属于最后手段。
5. **【确认稳定后】清理收尾**：把游戏目录停放项按需恢复（尤其是用户自己装的 SecondaryMotion 插件）、把 `runtime\migoto` 的旧 loader 文件删除、重新打包发布。
6. **【低优先】诊断包瘦身**：`runtime\logs\` 已积累 20+ 个 `diagnostics-*.zip`，可清理。

### 9.1 实测时验证"注入是否真的生效"（游戏运行中执行）

列出 `Endfield.exe` 里**非 System32、非游戏目录**的已加载模块 —— 那才是注入进进程的东西：

```powershell
Get-Process Endfield -ErrorAction SilentlyContinue | ForEach-Object {
  $pid_ = $_.Id
  $_.Modules | Where-Object { $_.FileName -notmatch '\\Windows\\' -and $_.FileName -notmatch 'Endfield Game\\[^\\]+\.dll$' } |
    Select-Object @{n='pid';e={$pid_}}, ModuleName, FileName
} | Format-Table -AutoSize
```

判读：
- 出现 `...\runtime\builtin\XXMI\EFMI\d3d11.dll` → EFMI/3DMigoto 注入**成功**（这是我们要的）；
- 出现 `d3d12.dll` / `dxgi.dll`（游戏目录）或 `sbm.dll` → **第三方加载器代理又回来了**，按 §5.3 / §8.1 处理；
- 什么都没有 → 注入失败（看 `XXMI Launcher Log.txt` 的 `Successfully injected DLL` 行）。

## 10. 坑与注意事项

1. **`.bak` 不是控制器写的**：控制器的备份名是 `*.endfieldmodcontroller.bak`；游戏目录里的 `d3dcompiler_47.dll.bak` / `vulkan-1.dll.bak` 是更早的"一键工具/手工替换"留下的，但内容确是原版，本次就是靠它们还原的。
2. **判定注入不要看文件名**：ReShade 正常情况下也会叫 `d3d12.dll`。一律用 `looks_like_loader_proxy()` 的标记扫描。
3. **别手工改 NVIDIA 的两个 json**，会被 NVIDIA App 覆盖。
4. **`plugin\` 不是游戏原生目录**（游戏原生是 Qt 的 `plugins\`）：`<game>\plugin\*.dll` 只可能来自第三方加载器。
5. **启动日志判读**：`runtime\launch.log` 记控制器动作；游戏目录的 `loader_log.txt` 只有第三方代理才会写（正常应为空文件）。
6. **前端改动后必须 `node --check web/app.js`**：JS 语法错误会让整个 UI 空白（Mod 库为空那一课）。
7. **打包前先跑测试与 self_check**，再更新文档里的 SHA256。
8. **`3dmloader.dll` 属于 XXMI-Libs 包**（`Resources\Packages\XXMI`），不是 EndfieldModController 的文件，不要误删。
9. 涉及反作弊/账号风险，向用户说明时保持原始措辞：Mod 有 ToS / 账号风险，首次使用先备份。
10. **启动终末地前先确认没有别的 3D 程序在跑**（尤其全屏游戏，例如 War Thunder）：两个 3D 程序抢 GPU 会让两边都异常，也容易把"卡顿/退出"误判成注入问题。启动 XXMI / 游戏前先截图确认桌面现状。
11. **不要无参调用 `prepare()`**：`EndfieldModControllerApi.prepare(active_ids=None)` 会走 `selected_ids=[]`，同时把 `config.selected_mods` 一起清空并保存，等于把全部角色 Mod 从 staging 里删掉。要保留用户选择就显式传 `api.config.selected_mods`。
12. XXMI Launcher 的 `auto_update` 为 **True**（`XXMI Launcher Config.json`）：它启动时会检查 Launcher / XXMI-Libs / EFMI 三个包。当前三者都是最新（2.2.1 / 1.1.7 / 1.4.7）所以不会自动改动，但**测基线时要注意它可能自己升级**，那会破坏"整套版本一致"这个前提。
