## 一、安装与首次启动

### 下载与放置

1. 到 [Release](https://github.com/jing-hy/EndfieldModController/releases) 下载 `EndfieldModController.exe`
   （同页还有一个 `assets-bundle.zip`，是随包组件，首次启动会自动处理）；
2. 放到一个**你有写权限的普通目录**再双击。程序会请求管理员权限（UAC 弹窗点"是"）——
   注入器本身要求管理员，非管理员启动会直接报错。

> ### ⚠️ 数据根 = exe 所在目录
> `config.json`、`runtime\`、`library\`（你的 Mod 库）都生成在 **exe 旁边**。
> 所以**别把 exe 放进 `Program Files` 这类只读目录**，也**别放临时目录**
> （清理工具会连你的 Mod 库一起删掉）。换机器时整个文件夹拷走即可。

### 首次启动会发生什么

1. **界面立刻出现** —— 窗口 1~3 秒内出现并显示加载页，加载页会分步说明当前在做什么
   （正在绑定界面 → 正在读取配置 → 正在扫描 Mod 库…）。**不会出现"窗口亮着一片空白"的阶段**；
2. 自动下载安装注入器、注入库、服装 Mod 引擎等组件（带校验）；
3. 注入器的配置文件是**它自己首次运行时生成**的，所以程序会先替你拉起一次、生成配置后关闭，
   并提示：

   > 第一次启动可能失败 —— 建议再启动一次。
   > 点了注入器里的 Start 之后，游戏有概率不会正常启动；如果发现游戏没开起来，**再启动一次**通常就好。

   （这个提示只在确实拉起过注入器、或还没走过首次引导时出现一次，不会反复弹。）
4. **再点一次「一键启动」**，这次会真正写好注入库并拉起注入器。

### 从源码运行（可选）

```bat
pip install -r requirements.txt
run.vbs            :: 无控制台窗口（推荐）
run.bat            :: 带依赖兜底与错误提示，会闪一个 cmd 窗口
run.bat --cli      :: 不开界面，直接打印当前状态 JSON
```

### DLSS5 装完直接玩，不需要手动配置

出帧所需的全部条件（shader 标准头与纹理、神经渲染运行库、运动矢量来源、preset 里两个效果的启用
与顺序）都由初始化自检自动写好并每轮校验 —— **不需要你进游戏点任何东西**：
一键启动 → 进游戏 → 面板里的「成功NR帧」应该就开始涨。

想确认它真在工作，看 `runtime\dlss5\dlss5-feed.log`，成功时是这样：

```
################ feed: opening D3D12 session ################
[feed] NVSDK_NGX_D3D12_Init -> 0x00000001 (Success)
[feed] feature ready: 3840x2160 DLAA, flags=74 ...
[feed] frame 1 delivered (3840x2160, reset=1)
```

万一没出帧，按「逐项排查」里 DLSS5 那一组顺序查。

## 二、四个页面怎么用

### Mod 库页

**导入**：把压缩包拖进窗口 → 出现全屏提示框 → 松手即导入（只有这一页接受拖放；
拖出窗口或按 Esc 取消）。支持 **`.zip` / `.7z` / `.rar`**。加密包、缺分卷、坏包都会给出可读原因，
且**不会在 `library\` 里留下半成品目录**；解压出来一个 `.ini` 都没有时会提示"可能不是有效的服装 Mod 包"。

**角色识别**：导入后按 Mod 名与 ini 里的线索猜角色。识别依据有三类写法 ——
中文名（含常见误译与社区昵称，如「小羊」=艾尔黛拉、「杰哥」=洁尔佩塔）、官网英文代号、
**中文拼音**（下划线、连字符、空格、大小写都不影响）。**认不出就直接弹窗让你选**
（下方已按"最可能的角色"预选），也可以稍后点卡片上的「角色待确认」。
角色表以**官网**为准，程序启动后会在后台与官网对一次，上新干员时自动并入新角色，
你手工补的社区简称与拼音别名一律保留。

**卡片**：右下角「⋯」是就地弹出的小菜单 ——
**更换 Mod 归属… / 修复 / 回滚修复 / 打开所在文件夹 / 移出 Mod 库**，
菜单顶部会显示当前归属与是否修复过。已修复过的卡片带「✓ 已修复过」标记；
库页顶部另有「一键修复所有 Mod」。修复用的社区工具没就位时，这一项是置灰的，
悬停会告诉你该把工具放在哪。

**勾选**：勾选即保存（同角色自动互斥），点「生成控制器」把选择落成注入器要加载的内容。

> ### ⚠️ 你的 Mod 库是只读的
> 程序**任何情况都不会**删除、移动或"整理" `library\` 里的东西 —— 重装组件、更新依赖、
> 清理中转目录、净化游戏目录，都不会碰它。**唯一**会改动库的动作，是你在卡片「⋯」里
> 主动点「移出 Mod 库」（移到 `runtime\backups\mod-trash\`，可找回）。
>
> 另外：**不要把「Staging Mods 目录」设成 Mod 库本身或它的上级/子目录** ——
> 清理中转目录是无条件删除，配错就等于删库。程序检测到这种重叠会**直接拒绝执行**并提示你怎么改。

**强行关闭角色 Mod 互斥**（库页顶部拨钮，默认关）：用于**部分同角色但不冲突**的 Mod
（例如一个改服装、一个只改贴图）。打开后勾选一个 Mod 不会再自动取消同角色的其它 Mod。
⚠️ 同角色两个 Mod 同时生效**常常**会让游戏崩，只在确认它们改的不是同一批资源时再开；
拨钮下方会显示当前状态。

**热键**：Mod 作者写的快捷键、以及它自带的控制菜单都**直接生效**。
「整合 Mod 快捷键」**不会锁这些键**，它只是多给一个遥控面板（见下文）。

### 启动页

- **一键启动**：补齐组件 → 同步注入库 → 初始化自检 → 拉起注入器。
  启动过程会在按钮下方**分步显示当前在做什么**（例如「正在重建 Mod 目录…」），慢的时候你能看见它在干活。
  不自动进游戏 —— 进游戏由注入器界面或「启动游戏」按钮完成。
- **打开官方 XXMI**：只打开它自己的界面，不动注入库。
- **强制关闭**：收掉残留的 loader / 游戏进程（**不会**在你没要求的情况下强杀正在玩的游戏）。
- **各插件开关**：DLSS5 神经渲染、第一人称、服装 Mod、物理效果、摆姿、整合面板，都能单独开关
  （靠移动文件实现，可逆）。

### 依赖页

显示各组件的状态（绿=已就位 / 红=缺失）、下载速度与实时日志。缺什么点「安装缺失依赖」；
想更新到最新点「一键更新全部组件」。

**「导入随包 zip…」**：给离线环境用的 —— 可以导入完整的 `assets-bundle.zip`，
也可以导入单独一份组件 zip。这是**依赖组件**的入口（**不是 Mod 包**，Mod 走 Mod 库那条路）。
导入前会**逐条校验**：清单要能解析、它列出的每个文件的**全部分卷都得在包里**，
缺一卷就拒绝并列出缺什么，且一个文件都不落盘。

### 设置页

路径配置（注入器 / 游戏 / loader / 物理工具 / Mod 备份目录）、下载加速与线路、主题、
单实例与游戏多开防护、依赖清单、日志与诊断包、游戏目录净化与还原等都在这里。

**用你自己已经装好的那份注入器环境**：如果你原本就有一份装好 Mod 的环境，
可以让本程序只做编排、不再动它 —— 在设置页把注入器路径与「Staging Mods 目录」指到你那份，
并关掉「使用内置运行环境」。之后程序既不会下载/更新自带那份，也不会改你填的路径。
想换回来反向操作即可。

> **关于「部署新版 nvngx」**：默认**关闭**，不确定就别开。DLSS5 的神经渲染接口住在
> `nvngx_dlssnr.dll` 里，程序会把它放在 `runtime\dlss5\` 供插件加载，
> **游戏目录里那份保持游戏原版即可**。打开这个开关会额外用新版覆盖游戏目录
> （改前留 `*.game_original`），**可能影响游戏启动**。

## 三、游戏内统一面板

Mod 自带的按键各不相同（`←`、`Ctrl+5`、`Alt 0`…），装多了不仅容易记混，
**还常常互相抢同一个键** —— 好几个 Mod 都用 `→`/`←`/`↓`，手按时谁被触发说不清。

启动页的「**整合 Mod 快捷键**」（默认开启）会把统一面板放进 ReShade：
进游戏按 **`Home`** → 切到 **ModeController** 页，按角色 / Mod 分栏，**每一项就是一个按钮**。

- **点一下 = 按一次这个 Mod 自己的那个键**。想连切几档就连点几下（点完面板不会自己关）。
- **它不锁你的按键** —— 你手按原键照常有效，面板点同一项效果一样，两者可以混用。
- 面板还能调**界面大小**（0.75×～2×，会记住）和一键**重置面板布局**（标签栏被挤出屏幕时用）。
- 面板**不显示开/关状态**：那个状态活在游戏进程的内存里，任何"开/关"显示都是编的。
- 面板装不上时会说明原因（面板日志在日志页能看到）。
- **中文显示**：ReShade 默认字体没有中文字形，程序会自动指向系统中文字体；
  真的拿不到中文字形时面板会自动改用英文标签。

## 四、Mod 下载

Mod 库页点「下载 Mod」→ 弹窗里一个输入框，**一行一个 `http(s)` 直链**：

1. **并行下载**（最多 4 个任务同时跑；慢时临时分块、直连不通临时换镜像线路、断点续传、sha256 校验）；
2. 先下到 `runtime\downloads\` 临时目录，**不直接写库**；
3. **能解压的自动解压进库**并识别角色 —— 与"拖进来"完全同一条链路，结果一致；
4. **不能解压的**（不是 zip/7z/rar，或包本身坏了）：**不清文件**，标成「需手动解压」，
   把路径写在界面上，并给「打开下载目录」按钮；
5. 一批结束给汇总：`入库 N · 需手动解压 M · 失败 K`。失败会如实写原因
   （HTTP 错误 / 校验失败 / 磁盘问题）。

### 香蕉网（GameBanana）适配

粘 `https://gamebanana.com/mods/<id>` 这类页面地址即可，程序自动换成真实文件直链，
并带出**封面图**、作者、版本信息。一个提交有多个版本时取最新的那个（会注明"共 N 个文件，已取最新"）。
**访问不上**（超时 / DNS / 证书 / 地区限制）会弹窗提示检查 VPN 或加速器后重试，
**同一批里的其它链接照常完成**（一个失败不牵连别人）。

## 五、Mod 备份

程序旁边会有一个 Mod 备份文件夹（默认 `<数据根>\mod-backup\`，可在设置页改到别处，
留空恢复默认）。**库里一出现新导入的 Mod，就整份复制进去**：一个 Mod 一个文件夹，**不压缩**。

- **只增不减** —— 程序里**没有任何删除或覆盖已有备份的代码路径**；想清理就自己删。
- 只处理还没备份过的 Mod，所以之后的启动是毫秒级；扫描与复制都在后台，不卡界面。
- 一个 Mod 复制失败只记一笔，整批继续。
- **绝不碰库**：只读 `library\`、只写备份仓。备份目录与库/中转目录**重叠**时整体拒绝执行
  （否则备份会落进库里越滚越大），界面会提示你改路径。
- 复制用"先写临时目录、成功后再改名"，中途失败不会留下"看起来备份了"的半份东西。
- 设置页能看到备份了几个、占多大，也能一键打开。

## 六、依赖组件（RabbitFX 这类前置）

像 **EFMI RabbitFX** 这种"shader 特效前置"，服装 Mod 会通过 ini 引用它。
程序不把它当皮肤 Mod，而是统一放在 `<Mod 库>\_deps\<名字>` 下维护。

- **按需激活**：**只有被你勾选的 Mod 真的引用了它**，才会被放进中转目录。
- **去重**：同一个依赖只维护一份，不会因为多个 Mod 引用就复制多份。
- **内外优先级**：库里已有同名依赖时按既定优先级取用，不会覆盖你放的那份。

## 七、目录结构

```text
<exe 所在目录>/
├─ config.json                  运行配置（原子写；损坏会被隔离成 config.json.broken-<时间戳>）
├─ library/                     Mod 库（你拖进来的包解压到这里）
├─ mod-backup/                  Mod 备份仓（只增不减；可在设置页改到别处）
└─ runtime/
   ├─ builtin/XXMI/             自动下载安装的注入器 + 注入库 + 服装 Mod 引擎
   ├─ dlss5/                    DLSS5 底座与插件（ReShade 底座 / *.addon64 / 运行库 / shader）
   ├─ reshade/                  控制器自己的插件与动作清单
   ├─ secondary_motion/         物理效果工具（可选）
   ├─ poser/                    摆姿 / MMD 播放安装包（从官方 Release 下载，不随包分发）
   ├─ game_backup/<时间戳>/      游戏目录净化备份（可还原）
   ├─ backups/                  引擎目录、配置等的历史备份
   ├─ logs/                     日志与诊断包（logs/bundles/*.zip 是崩溃包）
   └─ _update/                  自更新下载与残留
```

`library\` 与 `mod-backup\` 是**你的数据**，任何自动清理都不会碰它们；
控制器自己的产物一律带 `MC_` 前缀，便于区分。

## 八、逐项排查

### DLSS5（面板显示不正常时按顺序看）

**Q：面板显示「0 渲染」/ NGX Hook 创建 0？**
`nvngx_dlssnr.dll` 没就位。确认 `runtime\dlss5\` 里有这两个文件：
`nvngx_dlss.dll`（58,977,904 B）与 `nvngx_dlssnr.dll`（165,840,496 B）—— **游戏目录保持原版即可**，
不需要动它。日志里会有 `Failed to find NVSDK_NGX_D3D12_EvaluateFeature_C` 这一条，
**那是正常的**（它旁边的 `EvaluateFeature hooked` 才是关键）。

**Q：能进游戏，但「成功NR帧」一直是 0？**
正常情况不该出现（初始化自检会把下面三件事都办好）。真遇到了按顺序查
`runtime\dlss5\dlss5-feed.log`：

1. 有 `motion vectors will be zero (still images only)` ⇒ 运动矢量来源没配。
   重跑一次自检会补（需要 `DLSS5_MV_PROVIDER=1` 同时出现在两个配置里）；
2. 有 `could not open included file 'ReShade.fxh'` ⇒ 缺 shader 标准头，重跑自检补齐。
   注意 shader 纹理目录**空目录同样不行**；
3. 有 `LaunchPad technique found (DISABLED)`，或只有 `(enabled)` 却没有
   `opening D3D12 session` ⇒ preset 里的效果没有真正生效。**必须完全退出游戏后再改**
   （ReShade 退出时会把内存状态写回、覆盖你的改动）。兜底手段：进游戏按 `Home` →
   效果列表，把 `iMMERSE: Launchpad` 与 `DLSS5_Feed` 各点一次「置顶激活效果」
   （并保证 Launchpad 排在 DLSS5_Feed 之上），正常退出让 ReShade 自己写回。

**Q：ReShade 提示「编译一些效果时出现了错误」？**
那是完整 shader 集合里几个无关效果编译失败，**与 DLSS5 无关**，程序会把它们移走隔离。
真正要关心的是日志里有没有 `could not open included file 'ReShade.fxh'` ——
那说明缺 shader 标准头，重跑一次自检即可。

**Q：`dlss5-feed.addon64` 该用哪一版？**
**随包版和上游最新版都能用，不必刻意回退。** 判断它有没有工作**别只看版本号**，
看两处：`runtime\dlss5\dlss5-feed.log` 里有没有 `opening D3D12 session` → `frame N delivered`，
以及游戏内面板的「成功NR帧」是否在涨。

### 崩溃与自检

**Q：崩溃弹窗说「这次崩溃很可能由 Mod 资源冲突引起」，怎么办？**
说明你的 `Mods` 里有 Mod 覆盖了同一批资源（最常见是两个 Mod 改了同一个角色的同一批贴图/模型），
它们同时生效会让游戏在**加载过程中**闪退。按弹窗里的按钮直接去「Mod 库」页，
把冲突的两个里取消勾选一个 → 点「生成控制器」→ 再进游戏。清理后还崩，再把诊断包发出来。

**Q：点「一键启动」时弹出「启动前发现 Mod 冲突风险」？**
这是**拉起注入器之前**拦的一道确认，判据有两类（都是算好的事实，不是猜）：
**资源冲突**（两个 Mod 覆盖同一批资源）、**崩溃记忆**（这套组合以前真的崩过）。
点右侧橙色主选项「**先去清理，不启动**」（默认聚焦，直接按 Enter 也是它）会带你去 Mod 库页；
点左侧「仍然启动」才照常继续，但游戏有可能在加载过程中闪退。
（正常退出**不会**进崩溃记忆，不会因此打扰你。）

**Q：自检报「随包组件与基线不一致」？**
说明 `runtime\dlss5\` 里的组件和随包那一版**对不上**（多半是拿别的整合包覆盖过，
或者文件被改坏 / 解压不全）。

- **随包组件**（底座、运行库、几个插件）：**程序会自动按基线重新展开**，你不用管 ——
  你原来那份会备份成 `<文件名>.bak-before-baseline-restore`，想还原随时改回来。
  这类损坏很隐蔽：文件看着都在，表现却是**游戏每次启动几十秒后崩在显卡着色器编译器**。
- **可更新的组件**：**不会被自动改回去** —— 它本来就允许换成上游最新版。

**Q：某个文件老是被删掉、补上又缺，怎么办？**
多半是**安全软件把它当威胁隔离了**（最常见的是 165 MB 的神经渲染运行库，以及几个插件文件；
注意安全软件也可能直接删除而不是移入隔离区，从隔离区恢复没用）。
程序每次启动都会记一次"关键文件在不在"，**连续两次发现同一个文件不见了、且同组还有别的文件在**时，
会在你点「一键启动」后、补齐之前弹窗告诉你**具体是哪个文件**，并给出**建议加入白名单的目录**
（右侧橙色主按钮直接打开那个目录）。处理过之后不再重复弹。
（把文件改名成 `.disabled-by-mc`、或挪进 `_disabled\` 目录**算"主动停用"**，不会被误判成被删。）

**Q：点「修复」和点「一键启动」有什么区别？**
现在**两条链路完全一致**，都能自愈（都会补配置、补资产、重建内容、写注入库）。
修复过程中会自动打开日志窗，能看到每一步。

### 其他

**Q：物理效果工具每次都要我选游戏文件夹？**
它自己的设置里 `game_data_dir` 必须是 **`<游戏目录>\SecondaryMotion`**（数据目录，
**不是游戏根目录**）。程序初始化时会自动写好；手动改的话注意这一点。

**Q：第一人称没效果，点面板按钮也没反应？**
确认 `runtime\dlss5\ReShade.ini` 的 `[endfield-enhancer]` 段里
`CameraEFMICompatibility` 为 `1`（与服装 Mod 共存所必需）。
程序初始化时会写入一套可用默认值，重跑一次自检即可恢复。
切换键默认是 `F1`。

**Q：点了一键启动，Mod 没生效 / 注入失败？**
看启动页的自检结果与 `runtime\logs\launch.log`。常见原因：注入器配置还没生成
（第一次要点两次启动）、注入库被注入器自己的设置弹窗重置、游戏目录残留了旧的 loader proxy
（用「净化游戏目录」处理）。

**Q：游戏起不来 / 进游戏闪退？**
先看 `runtime\logs\bundles\` 里最新的崩溃包（程序检测到异常退出会自动打包，
里面有游戏的 `Player.log`、崩溃转储目录、模块列表与归因）。
已排除过的常见原因：注入库同时挂了两个 ReShade 底座、同角色 Mod 冲突、
游戏目录缺 `d3dcompiler_47.dll` / `vulkan-1.dll`。
**也不要同时开「部署新版 nvngx」。**

**Q：第一次启动会很慢吗？**
不会。窗口 1~3 秒内出现，而且**任何阶段都不会出现空白窗口**。
费时间的只有首次下载安装那几个组件；后台遍历盘符找工具是在首屏出来**之后**才开始的，
只影响设置页那几个「检测到的路径」字段，不影响你操作。

**Q：下载慢 / 连不上 GitHub？**
设置页把「下载加速」设为自动、线路设为自动即可：平时单连接，慢或断流时临时并发分块、
临时切镜像线路；**镜像下载物会用 Release 提供的 sha256 校验**，校验不过就丢弃重来。
用完线程池即销毁 —— 不常驻、不改 hosts、不装证书。

**Q：反作弊会不会有问题？**
本程序不注入、不碰反作弊；注入由注入器完成，且只作用于游戏目录里那几个已知文件。
所有对游戏目录的改动都可备份、可还原。风险自负（见免责声明）。

### 崩溃包 / 诊断包里都有什么

控制器日志、游戏自己的日志与崩溃转储、注入快照、Windows 事件、
**DLSS5 现场**（喂帧日志 / ReShade 配置 / preset），以及这次退出的**归因**
（Mod 冲突 / 其它崩溃 / 正常退出）。

另有几段判据：运行库指纹（精确字节与基线 sha256）、注入链摘要（每条注入文件在不在）、
shader 文件清单、运行时组件清单（每个文件的字节数 + sha256 前 16 位 + 是否偏离基线）、
以及**设备与显卡**段（CPU、内存、系统版本、每块显卡的名称 + 驱动版本 + 显存）——
用来一眼分清"这台机器是不是根本不支持"和"我们这边配错了"。

## 九、公告与异常状态预警

程序会联网读项目仓库里的公告文件，用来发布两类信息（作者改完推送即生效，不用发版）：

| 类型 | 行为 |
| --- | --- |
| **公告** | 启动后弹一次，看完即记已读、下次不再弹。**不锁启动** —— 点掉就完事 |
| **异常状态预警**（如大规模封号） | **每点一次「一键启动」都弹**，前端**强制停留**几秒（倒计时期间按钮不可点），必须三选一：**还原配置**（右侧橙色主选项、默认聚焦）/ 保持配置但不启动 / 仍然启动 |

**「还原配置」具体做了什么**（都能撤销）：① 关掉全部注入开关并按新开关重写注入库；
② 走游戏目录净化，把第三方文件**先备份再移走** —— 也就是回到"纯原版可启动"的最安全状态。
撤销入口在设置页；游戏目录文件用「一键还原游戏本体」搬回。

公告支持版本区间（只让特定版本的人看到），拉取失败一律静默跳过，不影响启动、更不拖慢首屏。
**正式版只从仓库读这份文件** —— 保护性的预警通道不留下"放个本地文件就能挡掉"的口子。

## 十、游戏目录净化 / 还原

把游戏目录里的第三方注入物（loader proxy、插件数据、残留 ReShade 痕迹）**先备份再移走**，
备份在 `runtime\game_backup\<时间戳>\`（含清单与还原所需的文件），随时可还原。
净化前会做**内容级判定**：内容不像注入载荷的 DLL **不会被误移走**
（例如游戏自带或他方放的正版文件）。设置页里全程可一键还原。

## 十一、摆姿 / MMD 播放（可选）

启动页第 5 个滑块。装什么、怎么装都由**它自己的安装向导**决定，本程序只做三件事：
**下载**（从它的官方 Release 取，带 sha256 校验）、**安装**（调它包内的部署脚本，
由向导写游戏目录并自带校验/原子写/失败回滚/安装记录）、**开关**
（关掉只把它的插件改个名，注入框架只扫 `*.dll`，所以立刻不生效，**不动 proxy、不动其它插件**）。

游戏内：按 **L** 开面板、**P** 冻结/解冻、按住 **Alt** 取光标、`Ctrl+F5/F6/F7/F8` 播放/暂停/停止/回首帧。
它还有一个独立摆姿页（游戏运行时用浏览器打开，启动页有按钮）。首次进游戏需要在游戏内确认它的用户协议。

**它和物理效果能共存**：两者用的是同一套注入机制（游戏目录里的 proxy 会把插件目录下所有
`*.dll` 加载进游戏进程）。所以卸载其中一方时，只要另一方还在，proxy 会被保留。

> 上游是 **AGPL-3.0**，本程序**不随包分发**它的二进制，只从官方 Release 下载并调用它自己的安装向导。

## 十二、常见问题（快速索引）

上面「逐项排查」里有完整版，这里只是指路：

| 现象 | 去哪看 |
| --- | --- |
| DLSS5 面板开着但不出帧 | 逐项排查 → DLSS5 |
| 进游戏没生效 / 注入失败 | 逐项排查 → 其他 |
| 游戏起不来 / 加载中闪退 | 逐项排查 → 其他，并导出诊断包 |
| 提示"某个文件缺失、补了又缺" | 逐项排查 → 崩溃与自检（安全软件白名单） |
| 崩了想知道原因 | 逐项排查 → 崩溃与自检，看崩溃包的归因 |
| 文件被删 / 想还原游戏目录 | 设置页 → 游戏目录净化与还原 |
| 下载慢 | 设置页 → 下载加速与线路 |

反馈途径见 **[简略版 README](../README.md#七反馈途径)** —— 两种方式都请**附上现象**
（什么时候出现、你点了什么、屏幕上看到什么）。诊断包里只有日志与设备信息，
**没有**"你做了什么"这一层。
