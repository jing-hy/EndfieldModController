## 二、已修复清单

### 2.1 安全（4 条）

1. **解压可越出目标目录（zip-slip 绕过）** — `api._extract_zip_into_long` / `api._extract_zip_into`
   原判据是字符串前缀 `str(dest/member).startswith(str(dest))`：`dest\..\foobar\x.ini` 的字符串**确实**以 `dest` 开头，
   于是校验通过，而写盘时 `..` 被解析 ⇒ 包里的文件落到 **Mod 库外面**（甚至覆盖库里别的 Mod）。
   现在统一走新增的 `fsutil.safe_join()`（拒绝绝对路径/盘符/UNC/任何 `..` 段）。
2. **GitHub token 被发给第三方站点** — `github.api_get`
   该函数不看 host，一律给请求加 `Authorization: Bearer <GH_TOKEN>`，而 `dependencies._fetch_json()` 拿它去请求
   `https://gamebanana.com/apiv11/...` ⇒ **用户的 GitHub token 被发给了 gamebanana**。现在按 host 白名单
   （`*.github.com` / `*githubusercontent.com`）才带凭据。
3. **任意文件删除/移动** — `reshade_integration.restore_game_dir_injections`
   清单里的路径没有任何"必须在游戏目录内"的校验，清单被改坏即可 `unlink()/rename()` 任意路径。
   现在与 `game_clean.restore` 一样强制 `is_relative_to(game_dir)`，并把一段死逻辑（"大小相同才删"被紧随其后的
   无条件 unlink 抹掉）改成真正生效。
4. **下载内容不校验** — `dependencies._download`
   GitHub Release 的 asset 自带 `digest`，但依赖包（会被**直接解压进 `_deps\`**）从不校验；现在带
   `expected_sha256`，且**缓存命中也要校验**（否则一个被截断的缓存会被无限复用）。

### 2.2 数据完整性 / 备份语义（P0，2 条）

5. **断点续传残留会让"坏包"报成功** — `moddl._cleanup_partial` + `fastnet`
   fastnet 的分块下载有两份产物：工作文件 `<名>.mcdownload` 与"哪些块已完成"的 `<名>.mcdownload.mcparts.json`。
   失败清理只删了前者 ⇒ 下次重试时 sidecar 还说"这些块下好了" ⇒ **跳过它们**，而工作文件是新建的空文件
   ⇒ 那些区间是空洞；块是 seek 写的、文件长度照样到总大小 ⇒ 上层"大小相等"判据通过 ⇒ **报成功并落位一个坏包**
   （rar/7z 只查文件头，坏包静默进 Mod 库）。现在：新增 `fastnet.discard_partial()`（唯一入口，删全部续传产物）
   供 `moddl` 复用；`_download_parallel` 另做交叉校验（块必须完全落在文件当前长度内才算"真有这些字节"）。
6. **「依赖清空重新下载」会删掉唯一的还原点** — `api.reset_dependencies_and_redownload`
   原顺序是「还原 → 无条件 `rmtree(runtime)`」，而 `restore_info` 的 ok/errors **返回后从未被检查**。
   `runtime\game_backup\` 是唯一一份"净化前"的游戏目录备份 ⇒ 还原失败时再删它，用户**永久**回不到原版。
   现在：还原未成功就**中止并如实说明**，不清任何东西。

### 2.3 备份语义（P1，已修 6 条）

7. **自更新回滚会让 exe 凭空消失** — `selfupdate.VBS_TEMPLATE`
   回滚分支是"先 `DeleteFile target`，再 `MoveFile backup, target`"，且整段在 `On Error Resume Next` 之下：
   第二步失败就是"程序没了、备份还在却没人知道"，脚本却照样写 "Rolled back to the previous version."
   现在改 `CopyFile`（保留 backup）+ 复核 target 是否真的存在，失败时把 backup 路径写进 `update-failed.txt`
   并且**不去启动一个不存在的 exe**。（同时保持模板纯 ASCII、补 `Dim rolled_ok`。）
8. **默认还原会挑中 `ngx-conflict-*` 备份** — `game_clean.list_backups` / `restore`
   两类备份混在一起排序，`'n' > '2'` 使 `backups[0]` **永远是** ngx-conflict 那份 ⇒ 点「从备份还原游戏目录」
   会把刚移走的 OptiScaler 原样搬回、DLSS5 又失效且无提示。现在清单带 `kind`（`clean` / `ngx_conflict`，
   旧备份按目录名推断）、`list_backups` 把净化备份排前面、`restore` 只认净化备份；`stamp` 与目录名也统一了。
9. **游戏目录 `ReShade.ini` 被整份覆盖** — `launcher._merge_disabled_addons`
   原来 `DisabledAddons` 整行**覆盖**（把用户已有的项静默删掉）、无备份、非原子写。现在：合并去重 +
   走 `_write_ini_atomic`（首次改动前留 `ReShade.ini.mc.bak` + 原子写）。
10. **备份名互相覆盖** — `reshade_integration.disable_game_reshade_proxies` / `disable_game_dir_injections`
    原来"若 `<名>.disabled` 已存在就先 unlink 再 rename"，而那份很可能就是**游戏自带的原始 dll**；
    且清单 `entries` 整份覆盖 ⇒ 旧条目的还原信息一起丢。现在用 `fsutil.unique_sibling`（备份只增不删）
    + 条目**追加合并**；名字推导也容忍唯一名后缀。
11. **假还原：备份丢了却报成功** — `reshade_integration.restore_global_reshade_apps`
    备份不存在时**什么都不做**，却返回 `ok=True, restored=[target]` 并删掉清单 ⇒ 界面说"已还原"，
    实际 `Apps=` 里没把 Endfield.exe 加回去且再也查不出原因。现在缺备份就 `ok=False` + 给出手工补法 + 保留清单。
12. **失败仍删清单** — `reshade_integration.remove_existing_reshade`
    删除/回拷失败全静默，随后**无条件删清单** ⇒ 之后无法重试还原、`.endfieldmodcontroller.bak` 成孤儿。
    现在只有全部成功才删清单，并如实返回失败项；备份文件也不再顺手删掉。

### 2.5 后端真实 bug（11 条）

27. **`api.py` 的 `__init__` 尾巴其实写在 `config` setter 里** — `api.EndfieldModControllerApi`
    那段（`_mod_dl` / `_mods_cache` / `_ui_ready` / 启动预热线程…）缩进属于 `@config.setter`。
    它之所以一直能跑，只是因为 `__init__` 里那句 `self.config = AppConfig.load()` **本身会触发 setter**。
    代价：任何 `api.config = xxx`（测试里就有）都会**重置正在进行的下载任务状态、清掉 Mod 缓存、
    换掉 `_ui_ready` 事件、并再起一个预热线程**（重复全盘扫描）。现已归位，并加 `_start_warm_up()` 保证只起一个。
28. **`set_mod_kind` 定义两次** — `api.py`
    后定义的旧版本覆盖了 2026-10-03 的新版 ⇒ 新版里"移到辅助 Mod 时清掉 `character`"的清理**从未生效**
    （辅助 Mod 一直残留角色归属，影响同角色互斥判据）。已删掉被覆盖那份并合并语义。
29. **`stage_and_prepare` 的 `zip(active_plan, active_targets)` 错位** — `activation.py`
    复制失败的 Mod 会 `continue`（这是你要的"不打断启动"），但 `active_targets` 只在成功时 append
    ⇒ 失败之后的每个 staged Mod 都拿到**下一个** Mod 的目录，`name` 与 `path` 从此错位
    （面板会把 A 的档位写到 B 的变量上）。已改为 `(mod, dest)` 成对记录。
30. **`_merge_preset_line(front=True)` 把顺序写反** — `initialize.py`
    对 required 逐个 `insert(0, …)` 会把列表**反序**：想要 `launchpad(provider) 在前`，实际写出来是 `feed` 在前，
    而 `DLSS5_Feed.fx` 要求 provider 排在它**上面** ⇒ 那次"顺序修正"实际没生效（addon 会报
    `provider is installed but DISABLED: enable it above DLSS 5 Feed`）。现在一次性 `items[:0] = missing`。
31. **DLSS5 preset 自检"停用了也报绿"** — `initialize._check_dlss5_preset`
    `enabled_map` 用**整份 preset** 的正则扫，而 `TechniqueSorting=`/`EffectSorting=` 两行本身就形如
    `Name@Effect.fx` 且列出**全部** technique（含未启用）⇒ 判据恒成立、永不修复。现在只扫 `Techniques=` 那一行。
32. **自检结果 `ok` 语义与前端约定冲突** — `initialize.Report.to_dict`
    `"ok": not pending`（"没有待处理项"）而全项目把 `{ok}` 当"接口是否成功" ⇒ 只要有**一条**需要用户处理的自检项，
    设置页就先弹「操作失败」并 **丢弃整份 checks/actions** ⇒ 自检功能除全绿外等于不可用。现在 `ok` 恒为
    "调用成功"，另给 `pending_count` / `pending`。
33. **GBK 的 `config.json` 会让程序起不来** — `config.AppConfig.load`
    `read_text(encoding="utf-8")` 抛的 `UnicodeDecodeError` **既不是 OSError 也不是 JSONDecodeError**
    ⇒ "坏了就隔离并重建"那条自愈分支完全走不到，异常直接冒到 `AppConfig.load()` 外面（构造 API 时没有 try）。
    现在复用新增的 `fsutil.read_text_tolerant()`。
    ⚠️ 顺带修掉一个**"能解码 ≠ 解对了"**的坑（验证时实测发现）：原来的候选顺序是
    `utf-8 → cp932 → gbk → latin-1`，而 GBK 的「暗色」（`B0 B5 C9 AB`）在 cp932 眼里是
    **能解码但不正确**的半角片假名 `ｰｵﾉｫ` ⇒ 中文配置值会静默变乱码。现在顺序为
    `utf-8-sig → utf-8 → gbk → cp932 → latin-1`（本项目以中文 Windows 用户为主），理由写在
    `fsutil._ENCODINGS` 上方。
34. **主题存不住** — `config.py`
    校验只认 `dark/light`，而前端有 6 套 ⇒ 用户选「琥珀/青蓝/紫罗兰/翡翠」下次启动被静默改回 light。
    现在 `THEMES` 与前端一致（并在注释里互相指向）。
35. **探测把"空结果"永久固化** — `config.auto_detect_migoto_loader` / `auto_detect_official_launcher`
    与同文件另两处（game_dir / xxmi）策略不一致：那两个只在非空时写缓存，这两个无条件写
    ⇒ 启动瞬间盘没就绪就会"永远定位不到 3DMigoto loader"。已对齐。
36. **`api.shutdown()` 一直在找一个不存在的函数** — `diagnostics.stop_process_monitor`
    于是"关窗口时停掉后台任务"是**空操作**：监视线程（最长 1800 秒）还会跑完并生成诊断包。
    已实现该函数（Event + 早退）并被 shutdown 调到；同时修了"拿不到进程句柄就空转 1800 秒"
    （游戏以管理员运行时 `OpenProcess` 失败 ⇒ 退出分支永不进入），现在降级为"按进程名消失"判据。
37. **`resume_mod_downloads` 没把 `done` 翻回 False** — `api.py`
    上一批 worker 结束时把它设成 True，而"继续"起的新批次没有翻回来 ⇒ 用户在这批还没跑完时点「开始下载」
    会被放行，**两个 worker 并发改同一份状态**。
38. **其余小项**：`start_full_update` 里 `asset_count = len(...) or 1`（进度分母凭空 +1，而 `_estimate_update_total`
    已为同一写法踩过坑并留了注释）；`log=progress and None`（恒等于 `None` 的死表达式）；
    `_import_archive_file` 用 `startswith` 找"刚解压的那个 Mod"（库里同时有 `foo`/`foo_bar` 时会认错）；
    `open_path` 的路径包含判定收敛到 `fsutil.is_within` + explorer 的子进程补 `CREATE_NO_WINDOW`；
    删掉无意义的死方法 `_json`。

### 2.7 逻辑不合理 / 自相矛盾（9 条）

39. `fastnet`：403/429 被**当成证书错误**处理 ⇒ 共用 30 分钟冷却（`LINE_RATE_LIMIT_TTL`=5 分钟这个常量、
    `rate_limited` 这个形参**从来没被用过**）。现在 403/429 走独立的 5 分钟冷却。
40. `deviceinfo._verdict` 用 `gen == 50`，而开关判据 `dlss5_supported` 是 `gen >= 50`
    ⇒ 未来更高代次会被开关放行、却在诊断包里读到"仅支持 50 系…属于支持范围问题"。已统一。

## 七、一句话总结

两轮下来修掉的，集中在"**看起来能用、其实没生效**"和"**有备份但还原不回去**"这两类：

* **前端 6 处"引用了不存在的名字"**（缺 `computed` / 缺 `showAlert` / 缺 `showProgressToast` /
  `sleep` 从未定义 / `store.refreshState()` 不存在）—— 每条都让一整条功能链路静默失效
  （冲突弹窗不弹、浏览按钮没反应、自动修复不执行、自动检测没提示）；
* **后端 2 个 P0**：断点续传残留让"空洞文件"报成功并进 Mod 库；「依赖清空重新下载」在还原
  失败时仍删掉**唯一一份**游戏目录还原点；
* **2 个安全漏洞**：解压可越出目标目录（zip-slip 用字符串前缀判断）、GitHub token 被发给
  gamebanana.com；
* **9 条备份语义**：备份名互相覆盖、假还原（备份丢了却报成功）、失败仍删备份索引、
  还原挑错备份（把 OptiScaler 当净化备份搬回去）、`.mc.bak` 没有还原创口、
  净化清单在动作之后才写导致"搬到一半的备份看不见"；
* **一批"能复用却不复用"**：原子写 3 套、JSON 读写 3 份、路径包含判定 4 份、编码容错 2 份、
  缓存目录 2 份、addon 移动 2 份 —— 全部收敛到 `fsutil` / 各自的唯一实现，并顺手把
  "抗杀软吃掉临时文件"的退避重试下沉成全项目共用。

**剩下没动的只有两类**：① 属"与外部依赖交互且不是备份问题"的 9 条（提权执行、taskkill 误杀、
全局 ReShade 三套实现、`d3dx_user.ini` 并发写…），只报不改；② 需要你拍板或会改变产物形态的
（诊断包要不要收全状态 json、主题双真相、`web/dist` 怎么走、一批后端能力缺前端入口）。
