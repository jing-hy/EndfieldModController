# 实际测试指南

这份指南用于验证 EndfieldModController 和 ReShade Addon 在你的真实终末地环境里能否工作。

> 所有操作前请先备份：
> - `%APPDATA%\XXMI Launcher\EFMI\Mods`
> - `%APPDATA%\XXMI Launcher\EFMI\d3dx_user.ini`
> - XXMI Launcher 的配置文件

## 0. 准备

1. 确认已安装 XXMI Launcher + EFMI。
2. 准备一个可用的 `ReShade64.dll`（Addon 版）。也可以运行 `python scripts/setup_reshade.py`，或使用 UI 设置页的“下载 ReShade Addon”按钮。
3. 准备至少一个测试 Mod 和一个依赖库（例如 RabbitFX）。
4. 不要把 Mod 直接放进游戏目录。

## 1. 配置程序

在 `endfieldmodcontroller` 目录运行：

```text
scripts\install.bat
run.vbs
```

`run.vbs` 不会显示命令行窗口；`run.bat --cli` 用于命令行调试。


或者：

```bash
python -m endfieldmodcontroller
```

设置页填写：

- `Mod 库目录`：例如 `D:\EndfieldModController\library`
- `Staging Mods 目录`：建议指向 XXMI 的 EFMI Mods，例如
  `C:\Users\<你>\AppData\Roaming\XXMI Launcher\EFMI\Mods`
- `XXMI Launcher 路径`：例如
  `C:\Users\<你>\AppData\Roaming\XXMI Launcher\Resources\Bin\XXMI Launcher.exe`
- `Endfield.exe 路径`：游戏目录下的 `Endfield.exe`
- `ReShade64.dll 路径`：你准备的 ReShade Addon DLL
- `注入方式`：先选 `external`
- `使用内置 XXMI/EFMI`：建议勾选，程序会自动下载/更新 XXMI 和 EFMI

保存设置。

## 2. 放入测试 Mod

目录示例（扁平布局也支持）：

```text
library/
├─ 测试服装/
│  ├─ mod.ini
│  └─ preview.png
├─ 测试角色/
│  └─ 测试服装2/
│     └─ mod.ini
└─ _deps/
   └─ RabbitFX/
      └─ mod.ini
```

回到 Mod 库页点击“重新扫描”，应该看到 Mod 卡片和封面缩略图。

## 3. 生成控制器

1. 用滑块开启一个角色 Mod；同角色其他 Mod 会自动关闭。
2. 点击“生成控制器”。
3. 期望：
   - 右侧状态显示动作数量；
   - `runtime/EFMI/Mods/_controller/controller.ini` 生成；
   - `runtime/reshade/actions.tsv` 生成；
   - `runtime/reshade/user_ini_path.txt` 生成；
   - 原始 `library` 里的 `key =` 没有被改；
   - staging 副本里的 `key =` 被替换成 `;MC_DISABLED key =`。

## 4. 依赖检查

到依赖页：

- `检查状态` 只跑 dry-run，不会下载。
- `自动安装/更新` 会依次处理内置 XXMI/EFMI、当前缺失依赖和已启用依赖。
- 没有启用、且当前选中 Mod 不需要的依赖会显示“无需”，不会误报缺失。
- 第一次建议先点“自动安装/更新”完成运行环境。

## 5. 启动

到启动页：

1. 点击“预览启动命令”。默认应该只打开 XXMI Launcher，不自动启动游戏，例如：

```text
XXMI Launcher.exe
```

   如果需要显式让 XXMI 启动游戏，可以用 `start_game=True` 的命令（`XXMI Launcher.exe --xxmi EFMI`）。它会打开正常的 XXMI Launcher 窗口，并由 XXMI 调起 `Endfield.exe`。
2. 点击“一键启动”。
3. 程序会：
   - 检查并修复完整性；
   - 安装缺失依赖；
   - 自动生成控制器；
   - 准备 `runtime/reshade`；
   - 如果检测到游戏目录已有 ReShade，写入 3 个集成文件并跳过外部注入；
   - 打开 XXMI Launcher，**不启动游戏本身**。
4. 在 XXMI 里确认当前 importer 是 `EFMI`，点击 Start；或直接在启动页点“通过 XXMI 启动游戏”。
5. XXMI/EFMI 会用 `-force-d3d11` 启动游戏；这是 mod 生效所需的 DX11 路径。

## 6. 游戏内验证

1. 按 ReShade 默认的 `Home` 打开 overlay。
2. 找到 `EndfieldModController` 面板。
3. 面板应该显示你勾选的 Mod 动作。
4. 点击一个动作。
5. 期望：
   - `d3dx_user.ini` 写入 `$\mc_controller\controller_action` 和 `controller_value`；
   - 程序发送 F10；
   - EFMI 重载后动作生效。
6. 按原 Mod 的快捷键，应该**不再生效**，说明快捷键屏蔽成功。

## 7. 结果记录

请重点记录：

- [ ] ReShade Addon 是否加载；
- [ ] `EndfieldModController` 面板是否显示；
- [ ] 点击动作后角色外观是否变化；
- [ ] 原 Mod 快捷键是否失效；
- [ ] 是否崩溃 / 黑屏 / 卡死；
- [ ] `d3dx_user.ini` 是否被正确修改；
- [ ] 同一角色切换 Mod 时旧 Mod 是否被移除。

## 常见问题

### ReShade Addon 没出现

- 查看游戏目录 `ReShade.log`，搜索 `endfieldmodcontroller.addon64`：
  - 如果出现 `Failed to register add-on, because the requested API version ... not supported`，说明 ReShade 版本过旧；
  - 如果出现 `Registered add-on "endfieldmodcontroller"`，说明 Addon 已加载，问题在 overlay 注册或输入。
- 如果游戏目录已有 ReShade，确认 `endfieldmodcontroller.addon64`、`actions.tsv`、`user_ini_path.txt` 都在游戏目录；
- `runtime/existing_reshade_files.json` 应该记录这 3 个文件；
- 如果游戏目录没有 ReShade，再检查 `ReShade64.dll` 是否是 Addon 版，或改注入模式为 `xxmi_extra`。
- 如果反作弊只报 `dxgi`，可以试“dxgi改名d3d12模式”：移走 `dxgi.dll`，保留 `d3d12.dll`。终末地动态加载 `d3d12.dll`，社区常用这个办法；如果反作弊连 `d3d12` 也报，就说明它检测的是 ReShade Hook 本身。

### 动作写了但游戏不变

- 当前设计需要 F10 重载；确认 F10 没有被游戏/其他工具占用；
- 确认 `controller.ini` 已复制到 staging `Mods/_controller/`；
- 确认 Mod 中的变量是 `global persist`；
- 检查 CommandList 全名是否匹配，例如 `CommandList\ChenSummer\ToggleBag`。

### 原快捷键还在

- 说明 staging 副本没有 patch 成功；
- 检查 `staging_mods_dir` 是否是 EFMI 真正读取的 `Mods`；
- 重新点击“生成控制器”。

### 启动提示 XXMI Launcher path is not configured

说明没有配置 XXMI Launcher 路径。

1. 确认已经安装 XXMI Launcher + EFMI。
2. 在设置页点击“选择 XXMI Launcher”，选中 `Resources\Bin\XXMI Launcher.exe`。
3. 或者点击“自动检测 XXMI”，如果本机装在常见位置会自动填入。
4. 保存设置后重新点击“一键启动”。

### 使用已确认可用的 3DMigoto Loader

如果本机已有能工作的 3DMigoto 包（含 `loader.exe`、`d3d11.dll`、`d3dx.ini`）：

1. 启动页点“启动 3DMigoto Loader + 官方启动器”；
2. 程序会把框架复制到 `runtime/migoto/`，把选中 Mod staging 到 `runtime/migoto/Mods/_endfieldmodcontroller_managed`；
3. 如果游戏目录有 ReShade 代理，会先隐藏 `dxgi.dll` / `d3d12.dll`；
4. `loader.exe` 以管理员权限启动，等待 `Endfield.exe`；
5. 官方启动器打开后，选择“使用 DirectX 11 启动”；
6. 进入游戏后 Mod 应由该 3DMigoto 包注入。

这个模式不加载 ReShade 游戏内 UI。需要恢复 ReShade 时点“恢复游戏目录 ReShade”。

### 游戏提示“被劫持 / 检测到软件加载行为”并拒绝启动

这通常是游戏目录里的 `dxgi.dll` / `d3d12.dll` 代理被反作弊识别。两种处理方式：

### 方式 A：dxgi改名d3d12模式（社区常见）

1. 点击“dxgi改名d3d12模式”；
2. 程序会把 `dxgi.dll` 改名为 `dxgi.dll.endfieldmodcontroller.disabled`，保留 `d3d12.dll`；
3. 终末地在 DX11 路径下也会动态加载 `d3d12.dll`，ReShade 仍可初始化；
4. 如需恢复，点击“恢复dxgi代理”。

### 方式 B：反作弊兼容模式（完全不保留游戏目录代理）

1. 点击“反作弊兼容模式”；
2. 它会移除我们写入游戏目录的 3 个集成文件，并把 `dxgi.dll` / `d3d12.dll` 都重命名为 `*.endfieldmodcontroller.disabled`；
3. 它会把现有 ReShade DLL 复制到 `runtime/reshade/ReShade64.dll`，并配置 XXMI `extra_libraries`；
4. 之后正常点“一键启动”，由 XXMI 注入 ReShade 和 EFMI；
5. 如需恢复原状，点击“恢复游戏目录 ReShade”。

如果两种方式后仍然报 `dxgi`/`d3d12` 或“软件加载行为被拦截”，说明反作弊检测的是 ReShade Hook 或 XXMI 注入本身。不要尝试绕过反作弊；只能选择不装 Mod，或接受账号风险。

### 一键启动没有注入 ReShade

- 如果游戏目录已经有 `ReShade.ini` + `dxgi.dll`，程序会跳过外部注入，改为把 Addon 写入游戏目录；这是预期行为；
- 这时请检查 `ReShade.log` 是否出现 `endfieldmodcontroller.addon64`；
- 如果游戏目录没有 ReShade，`external` 模式会等 `Endfield.exe` 出现后再注入，可能需要管理员权限；
- 也可以先手工把 ReShade 配好，再用 `none` 模式只验证控制器。

## 安全提醒

- Mod 和注入有账号风险。
- 不要关闭杀毒软件作为常规做法；只从官方渠道获取 ReShade 和 Mod。
- 本程序不会修改 `Endfield.exe` 或游戏 asset。
